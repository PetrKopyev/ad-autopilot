# Автопилот рекламы

Сервис, который сам ведёт рекламу малого бизнеса (маникюрный салон, йога-студия и похожие) в Яндекс Директе и VK Рекламе. Владелец описывает бизнес, подключает свои рекламные кабинеты и задаёт месячный бюджет. Дальше сервис сам создаёт кампании, останавливает неэффективные объявления, добавляет денег эффективным, проверяет пограничные объявления A/B-тестами и показывает расход, обращения и цену клиента простым языком. Каждое изменение записывается в историю с понятной причиной, и его можно откатить. Все решения принимает код по понятным правилам (см. [RULES.md](docs/RULES.md)); нейросеть YandexGPT/YandexART только пишет тексты и рисует картинки. Бюджет защищён четырьмя слоями, расход не должен превысить заданный.

## Быстрый старт: демо без ключей

Потребуется Node.js 20 или новее.

```sh
cd frontend
npm ci
VITE_MOCK=1 npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://localhost:5173). Интерфейс работает на заготовленных данных, без сервера, базы и ключей: вход, мастер запуска, статистика, объявления, история с откатом, клиенты, настройки.

## Демо

Полный стенд использует настоящий бэкенд и FakeAdapter. Ключи Яндекса, VK и Yandex Cloud не нужны: вход, чтение сайта, тексты и картинки работают без внешней сети. Каждый вход через «Войти в демо» создаёт отдельного пользователя и новый сценарий.

1. Скопируйте `.env.demo.example` в `.env.demo`. Задайте локальный пароль PostgreSQL одновременно в `POSTGRES_PASSWORD` и `DATABASE_URL` (используйте URL-безопасные символы), случайный `SECRET_KEY` длиной от 32 символов и Fernet-ключ в `TOKEN_ENCRYPTION_KEY`. Получить их можно через `secrets.token_urlsafe(48)` и `cryptography.fernet.Fernet.generate_key().decode()` в локальном Python. Не используйте секреты боевого сервиса.
2. Подготовьте фронтенд и backend-образ. Если зависимости ещё не установлены, установите их отдельно. Для текущего package.json используйте `npm install --package-lock=false` в `frontend`: закреплённая dev-зависимость Playwright добавлена без изменения lock-файла.
3. Выполните:

```sh
(cd frontend && npm run build)
sh deploy/demo.sh --build
# Повторный запуск без пересборки образа:
sh deploy/demo.sh
# Остановка (данные демо сохраняются в томах проекта autopilot-demo):
docker compose -p autopilot-demo --env-file .env.demo -f deploy/docker-compose.yml down
```

`deploy/demo.sh` запускает compose-проект `autopilot-demo` со своими томами, поэтому демо не попадает в базу боевого проекта. Скрипт отказывается запускаться, если `APP_DOMAIN` не `localhost`, а API с `DEMO_LOGIN=1` не стартует, если `APP_BASE_URL` указывает не на `localhost` или `127.0.0.1`. Compose использует `BACKEND_ENV_FILE=../.env.demo` из примера для передачи настроек API и воркеру. Боевой запуск по умолчанию продолжает использовать `.env`. Стенд публикуется на https://localhost; для локального сертификата Caddy браузер может попросить исключение. Compose применяет миграции при запуске, как и в боевом режиме.

Вход в демо принимается только со страницы стенда, не чаще 10 раз в минуту с одного адреса. Одновременно живут не больше 50 демо-пользователей: при каждом входе пользователи старше суток удаляются вместе с бизнесом, картинками и симулятором площадки.

Для проверки откройте `/login`, нажмите «Войти в демо» и самостоятельно пройдите пять шагов мастера. Сайт `https://salon.example/`, Москва и бюджет 30 000 ₽ уже подсказаны. Выберите цель «Заявка», подтвердите описание, затем заполните демонстрационные данные рекламодателя: ИП, контрольный ИНН `526317984689`, имя «Демо-салон», телефон `+7 900 123-45-67` и подтверждение маркировки. Эти значения используются только в ненастоящей площадке. Выберите картинки в плане и нажмите «Запустить рекламу».

На главной нажмите «+30 дней». Перемотка идёт в фоне: панель показывает, сколько дней пройдено, и по готовности обновляет экраны. Каждый получасовой шаг проходит через обычный `run_due`: появляются расход, обращения, остановки слабых, рост сильных и A/B с вердиктом. Дневные ограничения и месячный бюджет продолжают действовать. Если перемотка пересекает первое число, месячный бюджет обновляется при включённом автопродлении. В «Рекламе» проверьте «Остановлено нами», в «Истории» отфильтруйте «Автопилот», отмените одно изменение и верните фильтр «Все», чтобы увидеть «Вы отменили…». На главной доступны «Остановить всю рекламу» и «Продолжить».

За вызов разрешено 1–35 дней, всего 120 дней на бизнес. Пока идёт перемотка, другие изменения этого бизнеса отвечают «Идёт перемотка времени»; перемотки разных бизнесов идут независимо. После первой перемотки бизнес стоит на демо-дате: фоновый планировщик его пропускает, время движется только кнопками перемотки, повторная перемотка продолжает с той же даты. Состояние FakeAdapter хранится в памяти одного процесса API: после перезапуска войдите в новое демо. Масштабирование API на несколько процессов для этого стенда не поддерживается.

Сквозной Playwright-прогон запускается отдельно, только против уже поднятого стенда:

```sh
cd frontend
BASE_URL=https://localhost CHROMIUM_PATH=/path/to/chromium npm run e2e
```

Нужны закреплённый `@playwright/test` из devDependencies и заранее установленный Chromium. Без `CHROMIUM_PATH` используется заранее установленный браузер Playwright. Установка зависимостей и скачивание браузера не входят в скрипт и не запускаются в CI. Без `BASE_URL` сценарии пропускаются. Проверяются ширины 390 и 1280; скриншоты главной прикладываются к результатам в `/tmp/ad-autopilot-e2e`. Моки HTTP в этом тесте не используются.

## Тесты

Бэкенд (Python 3.12 или новее):

```sh
cd backend
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
ruff check .
pytest -m "not db"
```

Тесты с базой (`-m db`) нужен PostgreSQL. Укажите его в `TEST_DATABASE_URL` с драйвером psycopg (не asyncpg) и сначала примените миграции: тесты, кроме миграционного, схему сами не создают.

```sh
export TEST_DATABASE_URL='postgresql+psycopg://USER:PASSWORD@localhost:5432/autopilot_test'
DATABASE_URL="$TEST_DATABASE_URL" APP_BASE_URL=https://localhost SECRET_KEY=0123456789abcdef0123456789abcdef \
  TOKEN_ENCRYPTION_KEY="$(python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())')" \
  alembic upgrade head
pytest -m db
```

Фронтенд:

```sh
cd frontend
npm ci
npm run build                 # проверка типов и сборка в frontend/dist
VITE_MOCK=1 npm run build     # сборка с заготовленными данными, как в демо
```
