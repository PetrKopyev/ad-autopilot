# Автопилот рекламы

Сервис сам ведёт рекламу малого бизнеса (маникюрный салон, йога-студия и похожие) в Яндекс Директе и VK Рекламе. Владелец описывает бизнес, подключает свои рекламные кабинеты и задаёт месячный бюджет. Сервис создаёт кампании, останавливает неэффективные объявления, добавляет денег эффективным, проверяет пограничные A/B-тестами и простым языком показывает расход, обращения и цену клиента. Каждое изменение пишется в историю с причиной и откатывается. Решения принимает код по правилам из [RULES.md](docs/RULES.md); YandexGPT/YandexART только пишут тексты и рисуют картинки. Бюджет защищён четырьмя слоями, но абсолютной гарантии площадки не дают ([LIMITATIONS.md](docs/LIMITATIONS.md)).

Боевой стенд: https://avtopilot-reklamy.ru. 05.11 через него из мастера запущена настоящая реклама в Директе (три кампании, объявления с картинками) и подключён кабинет VK Рекламы. Решения автопилота на живых цифрах появятся, когда наберётся статистика; быстро увидеть их можно в демо.

## Демо за пять минут

Нужны Docker и Node.js 20+. Ключи Яндекса, VK и Yandex Cloud не требуются: площадки заменяет симулятор, вход, чтение сайта, тексты и картинки работают без внешней сети.

1. Скопируйте `.env.demo.example` в `.env.demo`. Задайте локальный пароль PostgreSQL одновременно в `POSTGRES_PASSWORD` и `DATABASE_URL` (URL-безопасные символы), `SECRET_KEY` от 32 символов (`secrets.token_urlsafe(48)`) и `TOKEN_ENCRYPTION_KEY` (`cryptography.fernet.Fernet.generate_key().decode()`). Секреты боевого сервиса не используйте.
2. Запустите:

```sh
(cd frontend && npm ci && npm run build)
sh deploy/demo.sh --build
# повторно, без пересборки: sh deploy/demo.sh
# остановка (данные сохраняются): docker compose -p autopilot-demo --env-file .env.demo -f deploy/docker-compose.yml down
```

3. Откройте https://localhost (браузер может запросить исключение для локального сертификата), `/login` → «Войти в демо».
4. Пройдите пять шагов мастера (сайт, город и бюджет подсказаны, цель «Заявка», тестовые данные рекламодателя подставлены — подтвердите маркировку), выберите картинки, «Запустить рекламу».
5. На главной нажмите «+30 дней»: появятся расход, обращения, остановки слабых объявлений, рост сильных и A/B с вердиктом (цифры симулятора условные, помечены «Демо»). Смотрите «Реклама» → «Остановлено нами», «История» → фильтр «Автопилот», отмена изменения.

Особенности демо:
- Каждый вход создаёт отдельного пользователя. Живёт не больше 50 демо-пользователей (старше суток удаляются при входе); освободить места сразу: `docker compose -p autopilot-demo --env-file .env.demo -f deploy/docker-compose.yml exec api python -m app.demo_reset`.
- За вызов перематывается 1–35 дней, всего 120 дней на бизнес; 30 дней занимают около 20 секунд.
- Состояние симулятора в памяти процесса `api`: после перезапуска войдите в демо заново.

Только интерфейс на заготовленных данных, без сервера: `cd frontend && npm ci && VITE_MOCK=1 npm run dev`. Сквозной тест Playwright против поднятого стенда: `cd frontend && BASE_URL=https://localhost CHROMIUM_PATH=/path/to/chromium npm run e2e`.

## Боевой режим

`DRY_RUN=false` (по умолчанию): автопилот применяет свои решения. `DRY_RUN=true` — режим наблюдения: решения автопилота (паузы, перенос бюджета, A/B, исправление отклонённых объявлений) только записываются как «предложено»; запуск из мастера, пересчёт лимитов, страж бюджета, действия владельца и откат работают всегда ([DEPLOY.md](docs/DEPLOY.md)).

Первые решения по цене на живом кабинете — не раньше чем через 5 дней после одобрения объявлений и набора 40 кликов за 14 дней ([расчёт](docs/LIMITATIONS.md#когда-появятся-первые-решения)).

## Тесты

Бэкенд (Python 3.12+; 2540 тестов без базы (+2 пропущено), 136 с PostgreSQL):

```sh
cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install --require-hashes -r requirements-dev.lock
ruff check .
pytest -m "not db"
```

Тесты с базой нужен PostgreSQL: укажите его в `TEST_DATABASE_URL` (драйвер psycopg), примените миграции, затем `pytest -m db`:

```sh
export TEST_DATABASE_URL='postgresql+psycopg://USER:PASSWORD@localhost:5432/autopilot_test'
DATABASE_URL="$TEST_DATABASE_URL" APP_BASE_URL=https://localhost SECRET_KEY=0123456789abcdef0123456789abcdef \
  TOKEN_ENCRYPTION_KEY="$(python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())')" \
  alembic upgrade head
pytest -m db
```

Фронтенд (327 тестов vitest): `cd frontend && npm ci && npm run build && npm test`.

CI (`.github/workflows/ci.yml`) на каждый push гоняет проверки бэкенда и фронтенда и e2e на демо-стенде.
