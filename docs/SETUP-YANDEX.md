# Настройка Яндекса

Нужны две вещи: приложение на oauth.yandex.ru (вход в сервис и подключение Директа и Метрики) и, для боевых текстов и картинок, каталог в Yandex Cloud. Все ключи задаются в `.env`, код менять не нужно ([DEPLOY.md](DEPLOY.md)).

## 1. Приложение на oauth.yandex.ru

1. Войдите в Яндекс под аккаунтом, который будет владельцем приложения, и откройте https://oauth.yandex.ru → «Создать приложение».
2. Платформа: «Веб-сервисы». Callback URI (redirect URI):

   ```
   https://<домен>/api/auth/yandex/callback
   ```

   Адрес должен в точности совпадать с `APP_BASE_URL` из `.env` плюс `/api/auth/yandex/callback` (так он строится в `backend/app/auth/yandex.py`). Один и тот же адрес используется и для входа, и для подключения Директа.
3. Доступы приложения. Названия в форме Яндекса могут отличаться, ориентируйтесь на идентификаторы, которые сервис запрашивает:

   | Идентификатор | Зачем |
   |---|---|
   | `login:info` | Логин пользователя Яндекса при входе |
   | `login:email` | Почта пользователя при входе |
   | `direct:api` | Доступ к Директ API от имени пользователя (запрашивается при подключении кабинета) |
   | `metrika:read` | Чтение счётчиков и целей Метрики (там же) |

   В форме это разделы «Яндекс ID» (логин, почта), «Директ» (использование API Директа) и «Метрика» (чтение статистики и параметров счётчиков).
4. Скопируйте ID и пароль приложения в `.env`: `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`. Перезапустите `api`: `docker compose --env-file .env -f deploy/docker-compose.yml up -d`.

Как работает вход: сервис использует код авторизации с PKCE и проверяемым `state`; токен Директа привязан к аккаунту, под которым пользователь нажал «Подключить Директ», а не к владельцу приложения. Поэтому свой кабинет подключает каждый пользователь сам, штатным сценарием в мастере запуска.

## 2. Доступ к API Директа

Для работы с реальным кабинетом приложение должно получить доступ к API Директа. Заявку подаёт разработчик, одна на ID приложения; после одобрения с приложением могут работать любые пользователи.

1. Нужен аккаунт в Директе, в котором есть хотя бы одна кампания, созданная в веб-интерфейсе: без неё страница с настройками API не откроется.
2. В интерфейсе Директа откройте «Настройки API» → «Новая заявка» и укажите ID приложения и описание: сервис автоматически ведёт рекламу владельцев малого бизнеса, каждый подключает свой кабинет.
3. Статус и причины отказа смотрите на вкладке «Мои заявки». По документации Яндекса срок рассмотрения от часа до трёх рабочих суток, в пик до семи дней. Подавайте заявку в первый день: без одобрения не работает даже песочница. Тот же доступ нужен прогнозу обращений на экране «Ваш план»: пока заявка не одобрена, вместо прогноза написано «Прогноз появится, когда Яндекс одобрит доступ к API Директа».

## 3. Песочница Директа

Песочница имитирует API, данные в ней изолированы, объявления не показываются.

1. Там же, в «Настройках API», вкладка «Песочница» → «Начать пользоваться»: выберите роль и валюту. Данные в песочнице удаляются через месяц после последнего обращения.
2. В `.env` задайте:

   ```
   DIRECT_SANDBOX=true
   ```

   Хост `api.direct.yandex.com` в обоих адресах API подменяется на `api-sandbox.direct.yandex.com` автоматически, `DIRECT_API_URL` и `DIRECT_API_V501_URL` менять не нужно.
3. Подключите кабинет через интерфейс как обычно: токен получается тем же способом.
4. Отчёты в песочнице отдаются по одной кампании; сервис запрашивает их по очереди. Какие обращения к Директу ещё не проверены на песочнице, перечислено в [LIMITATIONS.md](LIMITATIONS.md).

Для боевого режима верните `DIRECT_SANDBOX=false`.

## 4. Маркировка рекламы

Для Директа нужно заполнить данные рекламодателя (ИНН, название или ФИО, телефон). Сервис просит их в мастере запуска и передаёт в Директ через API; если API их не принимает, показывает инструкцию: в Директ Про открыть «Данные рекламодателя», заполнить поля, сохранить согласие на передачу в ЕРИР. ERID для креативов назначает Яндекс. Объявления в Директе не включаются, пока рекламодатель не подтвердил, что данные заполнены.

## 5. YandexGPT и YandexART (Yandex Cloud)

Нейросети используются только для текстов объявлений, черновика описания бизнеса и картинок. Решений о рекламе они не принимают ([ARCHITECTURE.md](ARCHITECTURE.md)).

1. В консоли Yandex Cloud (https://console.yandex.cloud) создайте или выберите облако и каталог, подключите платёжный аккаунт. Идентификатор каталога возьмите на странице каталога, это `YC_FOLDER_ID`.
2. Создайте сервисный аккаунт в этом каталоге и назначьте ему роли на вызов моделей: `ai.languageModels.user` (YandexGPT) и `ai.imageGeneration.user` (картинки Alice AI ART). Названия ролей приведены по документации Yandex Cloud, проверьте их в списке ролей консоли.
3. Для сервисного аккаунта создайте API-ключ и сохраните значение в `YC_API_KEY`. Ключ показывается один раз. В области действия ключа отметьте обе: `yc.ai.foundationModels.execute` (тексты) и `yc.ai.imageGeneration.execute` (картинки). Без второй области и роли `ai.imageGeneration.user` картинки не создаются: API отвечает 403.
4. В `.env`:

   ```
   YC_FOLDER_ID=<идентификатор каталога>
   YC_API_KEY=<API-ключ сервисного аккаунта>
   YANDEXGPT_MODEL=yandexgpt/latest
   YANDEXART_MODEL=aliceai-image-art-3.0/latest
   ```

   Тексты сервис пишет моделью `gpt://<YC_FOLDER_ID>/<YANDEXGPT_MODEL>`, ключ передаётся заголовком `Authorization: Api-Key`. Картинки рисует `art://<YC_FOLDER_ID>/<YANDEXART_MODEL>` через OpenAI-совместимый API (`POST https://ai.api.cloud.yandex.net/v1/images/generations`, заголовки `Authorization: Bearer <YC_API_KEY>` и `OpenAI-Project: <YC_FOLDER_ID>`), квадрат 1024×1024 в JPEG, 10–15 секунд на картинку. Старые `yandex-art/latest` и `yandex-art-2.0/latest` не используются: первая отвечает 403, вторая на 28.10.2026 завершала операции ошибкой 13.
5. Если `YC_API_KEY` или `YC_FOLDER_ID` пусты (а также при `PLATFORM_MODE=fake`), сервис работает с заглушками: шаблонные тексты и случайные картинки.

Стоимость: по данным исследования на 26.10.2026 YandexART стоит 2,23 ₽ за запрос с НДС; тариф Alice AI ART не сверен, в учёте трат картинка считается по той же цене (`ART_COST_KOP` в `backend/app/content/art.py`). Отклонённый запрос (ошибка 4xx или 5xx, сеть недоступна) в траты не идёт. YandexGPT Pro 5.1 стоит 0,8 ₽ за 1000 токенов. Расходы на нейросети считаются отдельно от рекламного бюджета и ограничены `AI_SPEND_ONBOARDING_LIMIT_RUB` (60 ₽ на подготовку плана) и `AI_SPEND_WEEKLY_LIMIT_RUB` (25 ₽ в неделю) на бизнес. Тариф в учёте трат зашит в коде для Pro 5.1: при смене модели в `YANDEXGPT_MODEL` учёт будет приблизительным.
