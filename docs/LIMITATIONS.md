# Ограничения и что не проверено

Бэкенд проверен автотестами без внешней сети (2540 без базы (+2 пропущено), 136 с PostgreSQL), интерфейс — 327 тестами vitest и сквозным Playwright на ширинах 390 и 1280, площадки — симулятором `FakeAdapter`. На живых площадках проверено только перечисленное ниже.

## Что проверено вживую

- Директ (боевой кабинет, 31.10–01.11, 03.11, 05.11): чтение справочников и кампаний, создание дерева, `moderate` → `resume`, вариант A/B (`add_ad`), загрузка картинок, статистика с целями, единая перфоманс-кампания `UnifiedCampaign` и `ResponsiveAd` (v501). Доступ к API одобрен 31.10. Песочница 03.11 отвечала 504 на стороне Яндекса; при развёртывании её можно включить `DIRECT_SANDBOX=true`, если отвечает.
- 05.11 на проде (https://avtopilot-reklamy.ru) из мастера запущено три кампании Директа с объявлениями и картинками; подключены Метрика и кабинет VK (по ключу API). На момент написания объявления ещё проходили модерацию.
- VK (31.10–02.11): доступ, гео-дерево, чтение списков. Создание плана упирается в требования VK (ниже).

## Не проверено на живых площадках

Яндекс Директ:

- Передача данных рекламодателя `Clients.update` (`ErirAttributes`): кабинет вернул «данные не переданы», владелец заполняет их в кабинете, сервис показывает инструкцию.
- `WeeklySpendLimit` с датой окончания как жёсткий лимит расхода. НДС: сервис считает суммы стратегии без НДС (`лимит ÷ 1,22`, `DIRECT_AMOUNTS_INCLUDE_VAT=false`); сверьте лимит в интерфейсе и в API и трату за неделю. Если суммы API окажутся с НДС — `DIRECT_AMOUNTS_INCLUDE_VAT=true` (пока сервис недотрачивает около 18%, но не перерасходует).
- Замена картинки (`Ads.update`).
- Остаток общего счёта (`AccountManagement`, `Amount`): с НДС или без — не подтверждено, берётся как есть.
- Включение после модерации проверено тестами: `State=OFF` после одобрения сервис включает, `SUSPENDED` считает паузой владельца (если Директ отдаёт `OFF` и для остановленного владельцем, такую кампанию сервис включит); шаг идёт раз в час.
- Новая группа в работающей кампании для проверки аудиторий (`AdGroups.add`, `Keywords.add`, `add_group`).
- Прогноз обращений (`direct_forecast.py`, API v4 Live): стоимость вызова в баллах, единицы цен (с НДС или без), смысл полей `Min`/`Max` и `Clicks`/`FirstPlaceClicks`, коды ошибок 58, 31, 53, 52/152, точность против факта; в Метрике — идентификатор `ya_direct` и значения `ym:s:goal`. При ошибке прогноз пишет «ориентир» с причиной. Список «своих» отчётов прогноза хранится в памяти `api`: после перезапуска при ошибке 31 они не опознаются и освобождаются сами за пять часов.

VK Реклама (допущения собраны в `API_FORMAT` в `backend/app/platforms/vk.py`):

- Создание плана на живом кабинете не прошло: `package_id` обязателен; для пакета с `site_conversions` нужна цель пикселя `priced_goal` (цели Метрики через API не привязываются; `source_id` счётчика Метрики отвергнут), а баннеры не создаются без заполненной маркировки ОРД в кабинете. Сервис перебирает пакеты и, не найдя подходящего, останавливает запуск с инструкцией. Цель пикселя задаётся в «Настройках» → «Цель ВКонтакте» (запасной вариант — `VK_PRICED_GOAL_SOURCE_ID`). Запрос в поддержку VK — ads_api@vk.team.
- Вход через `authorization_code`: VK выдаёт его «при выполнении условий», они не раскрыты; запасной путь — ключ API.
- Бюджет: план держит только дневной лимит (`budget_limit_day`), месяц закрывает страж. Модель проверена тестами. Минимум дневного лимита 300 ₽ взят из справки VK, API его не отдаёт; запас 15% (от 345 ₽, бюджет от 48 500 ₽) выбран без замеров.
- Не проверены: частичное обновление плана, загрузка `content/static.json`, `add_group` (`POST ad_groups.json`), статистика `statistics/*/day.json` и по целям, `ord_user.json` (при 404 сервис просит заполнить маркировку в кабинете), баланс `user.json`, `X-RateLimit-*`, предел 5 токенов на связку.
- НДС: при `VK_AMOUNTS_INCLUDE_VAT=true` лимиты уходят как `лимит ÷ (1 + VAT_PERCENT/100)`; на живом кабинете не проверено.

Живые доказательства того, что отключение слабого, рост сильного, A/B и откат работают на реальных деньгах, появятся после набора статистики; сейчас они подтверждены симулятором и тестами. Совпадение статистики с кабинетами на данных со сравнимым трафиком не сверялось, соблюдение бюджета на реальных деньгах не проверено.

## Не реализовано

- Видео на площадки: сервис собирает видео из картинок (`ffmpeg`), но не отправляет (в Директе загрузка отклоняется, VK не вызывается).
- Правка текстов, картинок и города после запуска; пороги автопилота не настраиваются через `.env` и интерфейс (`backend/app/domain/settings.py`).
- Агентские кабинеты Директа: отклоняются при подключении с понятной ошибкой.
- Геотаргетинг — один город (словарь `CITY_REGIONS` на 16 городов, затем `GeoRegions` Директа и дерево регионов VK); при неоднозначном городе запуск просит проверить его. Несколько городов, радиус, районы — нет.
- Медицинские темы требуют документов рекламодателя и ручной подачи в поддержку Директа; сервис предупреждает и добавляет дисклеймер.
- Пополнение кабинетов, подача документов на модерацию и заявка на доступ к API выполняются вручную вне сервиса.
- Автопродление токена Директа по refresh-токену живьём не проверено; если оно не удалось и до конца токена меньше 7 дней, владельцу приходит уведомление «Переподключите Директ», после истечения кабинет переходит в `needs_reauth`.
- Отзыв токенов неполный: Яндекс отзывает только токены с `device_id` (кабинеты Директа, подключённые раньше, и токен входа через Яндекс ID снимаются в настройках Яндекс ID); при ключе VK отзываются все токены ключа; при переподключении старый токен не отзывается ([PRIVACY.md](PRIVACY.md)).
- Ограничение частоты запросов хранится в памяти процесса `api` (`backend/app/api/limits.py`), не делится между процессами; при нескольких репликах нужна внешняя защита (например `caddy-ratelimit`).
- Доля бюджета на A/B-тест (не больше 25% бюджета группы) выдерживается расчётом: площадка сама распределяет показы. Вердикт ждёт «охлаждения» после изменений в группе; что он не откладывается бесконечно, не проверено.
- Ввод ограничен: до 200 услуг и 200 строк цен, описание до 2000 знаков, бюджет до 10 000 000 ₽; в Директе ведутся первые пять услуг.
- Тариф YandexGPT (0,8 ₽ за 1000 токенов) зашит в `backend/app/services/registry.py`; при смене `YANDEXGPT_MODEL` учёт трат приблизительный. Недельный пул трат на ИИ привязан к Яндекс ID.
- `BUDGET_RESERVE_PCT` учитывается при плане и запуске; перебалансировка, страж и пересчёт считают с резервом 8%.
- `pip-audit` в CI не подключён.

## Когда появятся первые решения

На живом кабинете автопилот первые дни только смотрит ([RULES.md](RULES.md)):

- Цифры последних 2 дней ещё уточняются, по ним решения не принимаются.
- Первые 5 дней после одобрения объявления — разогрев, по цене его не оценивают.
- Для оценки по цене нужно не меньше 40 кликов за 14 дней и опорная цена обращения (средний чек из настроек или хотя бы 3 обращения).
- Раньше возможны только остановки по явным признакам: 48 часов без показов после одобрения, 2000 показов с очень низким CTR, 80 кликов без обращений.

Срок до первых решений по цене — дни разогрева или 2 дня уточнения плюс дни набора 40 кликов, что дольше:

| Кликов на объявление в день | Первые решения через, дней |
|---|---|
| 20 и больше | 5 |
| 10 | 6 |
| 5 | 10 |
| 3 | 16 |
| меньше 2,9 | решений по цене нет |

Кликов на объявление в день = дневной бюджет площадки ÷ цена клика ÷ число работающих объявлений. Пример: 30 000 ₽ в месяц, весь бюджет в Директе (VK выключен), около 736 ₽ в день, клик 30 ₽ — около 24 кликов в день; на 3 группы по 2 объявления это 4 клика на объявление и первые решения примерно через 12 дней, на 5 групп — около 2,4 клика и решений по цене нет.

**A/B-проверки на малом бюджете не запускаются — это свойство порогов, а не сбой.** Текстовому A/B нужно пограничное объявление (40 кликов за 14 дней), аудиторному — тысячи показов в день на группу. На экране будет «Пока недостаточно данных или бюджета»; логику проверок можно посмотреть в демо («+30 дней»). Перенос бюджета между Директом и VK — не чаще раза в 14 дней.

На Главной под строкой состояния написано, когда ждать первых решений (`domain/rules.py:first_decision_days`).

## Нагрузка и пределы

- Доступ к базе из асинхронного кода синхронный сознательно (запросы миллисекундные); для одного процесса `api` и малого бизнеса достаточно.
- Блокировки бизнеса берутся без ожидания: пул занят — 503, бизнес уже обрабатывается — 409. Фото: JPEG, PNG, WebP до 10 МБ, не больше двух разбираются одновременно. Период статистики — до 400 дней.
- Пределы памяти контейнеров рассчитаны на VPS 2 ГБ + 2 ГБ swap ([DEPLOY.md](DEPLOY.md)).

## Демо

- Цифры симулятора условные и завышены (клики дешёвые, обращения частые): иначе A/B не набрали бы выборку за демо-перемотку; в интерфейсе они помечены «Демо». Симулятор реальную экономику не проверяет.
- 30 дней перемотки — около 20 секунд, одновременно не больше 10 перемоток (одиннадцатая получает 503). Состояние симулятора в памяти процесса `api`: после перезапуска войдите в демо заново.

## Свойства площадок

- Площадки соблюдают лимиты приблизительно: дневной расход может превысить лимит, недельный в Директе выравнивается задним числом, отчёты запаздывают. Поэтому четыре слоя защиты бюджета ([ARCHITECTURE.md](ARCHITECTURE.md)) снижают риск, но абсолютной гарантии на уровне площадки нет.
- Конверсии Метрики «доезжают» задним числом, решения принимаются по дням не позже «сегодня − 2», реакция автопилота запаздывает на 2–3 дня.
- API площадок не говорит, кто поставил паузу; автор определяется по журналу сервиса. Паузу и включение кампании в кабинете сервис замечает при пересчёте лимитов (раз в день и при «Возобновить»); объявления и группы, остановленные в кабинете, не отслеживаются.
- Если справочник минимумов площадки не ответил, берутся запасные из `PLATFORM_MINIMUMS` (`backend/app/domain/budget.py`).

## Известные особенности

- Первый запуск нового плана в месяце, где бюджет уже тратился, считает лимиты от полного месяца: до первого пересчёта (шаг воркера с 06:00) их сумма может превышать остаток; страж держит общий потолок.
- Проверка сайта при открытии плана идёт `GET`-запросами: при отсутствии кэша платный запрос к ИИ выполняется на чтение в рамках `AI_SPEND_*`; явный повтор — `POST /api/business/site-check`. Учёт трат на ИИ (`ai_spend_ledger`) удалением бизнеса или аккаунта не обнуляется.
