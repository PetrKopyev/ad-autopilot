# Ограничения и что не проверено

Здесь честный список: что проверено только на симуляторе и тестах с подставленными ответами, что не сделано и какие допущения нужно проверить при первом запуске на живых кабинетах.

## Не проверено на живых площадках

Бэкенд проверен автоматическими тестами (около 1200 тестов, без сети) и симулятором `FakeAdapter`. Прогон на песочнице Директа и на живом кабинете VK ещё нужно сделать: при развёртывании начните с `DIRECT_SANDBOX=true` и `DRY_RUN=true` ([DEPLOY.md](DEPLOY.md)).

Яндекс Директ, проверить в песочнице:

- создание единой перфоманс-кампании `UnifiedCampaign` и объявления `ResponsiveAd` через v501;
- `WeeklySpendLimit` вместе с датой окончания как жёсткий лимит расхода; поведение `CustomPeriodBudget`;
- передача данных рекламодателя через `Clients.update` (`ErirAttributes`); если API их не принимает, сервис показывает инструкцию вручную;
- замена картинки в объявлении (`Ads.update`);
- суммы в отчётах в микроединицах (`Cost`), отчёты по кампании, столбцы конверсий `Conversions_<цель>_LSCCD`, значение «--» в ячейках;
- включение кампании после модерации: после запуска возможно состояние «выключена», которое сервис должен считать успехом.

VK Реклама, проверить на живом кабинете (допущения собраны в `API_FORMAT` в `backend/app/platforms/vk.py` и `TOKEN_ERRORS` в `backend/app/auth/vk.py`):

- `authorization_code` для стороннего сервиса: VK выдаёт его «при выполнении условий», условия не раскрыты; запасной путь это ключ;
- тело `ad_plans.json`: цель `site_conversions`, стратегия `max_goals`, нужен ли `package_id` (сервис его не задаёт);
- ключи баннера и таргетингов, размеры изображений, фильтры списков и формат `{count, items}`;
- частичное обновление плана `POST /ad_plans/{id}.json`, загрузка `content/static.json`;
- статистика `statistics/*/day.json`: поля расхода строкой, причины модерации;
- поля `ord_user.json`, баланс в `user.json`, имена заголовков `X-RateLimit-*`;
- предел в 5 токенов на связку, повторный `client_credentials`.

## Не реализовано

- Отзыв токенов неполный. При отключении кабинета и удалении данных сервис отзывает токены на стороне площадок (`backend/app/auth/revoke.py`), но Яндекс отзывает только токены, выданные с `device_id`: кабинеты Директа, подключённые до этой правки, так не отзываются, их доступ пользователь снимает в настройках Яндекс ID. Токен входа через Яндекс ID (без `device_id`) не отзывается. VK удаляет сразу все токены пользователя в приложении, поэтому кабинет VK, который подключён и в другом бизнесе, не отзывается. Ошибка отзыва не мешает удалению, в журнал пишется только площадка и код ошибки. При переподключении кабинета старый токен не отзывается.
- Ограничение частоты запросов хранится в памяти процесса `api` (`backend/app/api/limits.py`): входы через Яндекс и VK, демо-вход, проверка сайта и обновление картинок. Счётчики сбрасываются при перезапуске и не делятся между процессами; при нескольких репликах `api` нужна общая защита перед сервисом (например модуль `caddy-ratelimit`). Адрес клиента берётся из `X-Forwarded-For` только от Caddy (`--forwarded-allow-ips`, см. [DEPLOY.md](DEPLOY.md)).
- Тома для картинок нет. `deploy/docker-compose.yml` не монтирует каталог для `MEDIA_DIR`, а контейнеры работают от пользователя без записи в `/app`. До исправления сборки загрузка фото и генерация картинок в контейнерах не заработают без ручной настройки ([DEPLOY.md](DEPLOY.md)).
- Бюджет теста не больше 25% бюджета группы выдерживается только расчётом. Тест идёт внутри группы, отдельного бюджета на вариант нет. При запуске проверяется оценка расхода теста, но площадка распределяет показы между объявлениями сама, ограничить долю жёстко нельзя.
- Вердикт A/B-теста может задерживаться. Он ждёт «охлаждения» после изменений в группе и кампании, включая ежедневную перебалансировку бюджета. Срок теста ограничен (14 дней, при продлении 21), но не проверено, что постоянные изменения в группе не откладывают вердикт без конца.
- `BUDGET_RESERVE_PCT` учитывается при подготовке плана и запуске; ежедневная перебалансировка, страж и ежемесячный пересчёт считают с резервом 8% по умолчанию. Менять резерв стоит только вместе с правкой `backend/app/domain/settings.py`.
- Пороги автопилота (`backend/app/domain/settings.py`) не настраиваются через `.env` и интерфейс; индивидуальных настроек на бизнес нет.
- Тариф YandexGPT (0,8 ₽ за 1000 токенов, Pro 5.1) зашит в код `backend/app/services/registry.py`; при смене `YANDEXGPT_MODEL` учёт расходов на нейросеть будет приблизительным.

## Свойства площадок

- Площадки соблюдают лимиты приблизительно: дневной расход может превысить лимит, а недельный в Директе выравнивается задним числом. Отчёты о расходе приходят с задержкой. Поэтому в сервисе четыре слоя защиты бюджета (резерв 8%, лимиты на стороне площадки с запасом 25%, страж каждые 30 минут, сверка при запуске), см. [ARCHITECTURE.md](ARCHITECTURE.md). Это снижает риск, но абсолютной гарантии на уровне площадки нет.
- Задержка конверсий. Конверсии Метрики появляются в отчётах Директа с задержкой до нескольких часов и «доезжают» задним числом по дате клика. Решения принимаются только по дням не позже «сегодня минус 2», последние дни в интерфейсе помечены как неполные. Из-за этого реакция автопилота на события запаздывает на два-три дня.
- Мало данных при малых бюджетах. Если показов и обращений мало, сервис не принимает решений по цене, а пограничные случаи отправляет в A/B-тест по CTR, а не по обращениям.

## Содержимое и охват

- Видео не отправляются на площадки. Сервис собирает видео из изображений (`ffmpeg`), но на площадки оно не уходит: в Директе загрузка явно отклоняется («Загрузка видео требует отдельного процесса AdVideos/Creatives»), у VK метод загрузки есть, но запуск и тесты объявлений его не вызывают.
- Геотаргетинг по одному городу. Для Директа сначала берётся словарь `CITY_REGIONS` (`backend/app/platforms/direct.py`, 16 городов-миллионников и «Москва и Московская область» = 1, по [справочнику регионов Яндекса](https://yandex.ru/dev/tasks-api/doc/ru/regions.md)), остальные города ищутся в справочнике `GeoRegions` API Директа внутри России. В VK город ищется в дереве `regions.json` внутри России (188), затем поиском по названию. Справочники кэшируются в памяти процесса на сутки. Если город не найден или название неоднозначно, запуск не выполняется с просьбой проверить город. Несколько городов, радиус и районы не поддерживаются.
- Медицинские темы (косметология и др.) требуют документов от рекламодателя и ручной подачи в поддержку Директа; сервис лишь предупреждает и добавляет дисклеймер.
- Пополнение рекламных кабинетов, подача документов на модерацию и заявка на доступ к API выполняются вручную вне сервиса.
- Демо-режим (`PLATFORM_MODE=fake`) хранит состояние симулятора в памяти процесса `api`: после перезапуска демо-запуск создаётся заново.
- Страницы описания сайта: сайты без текста или целиком на JavaScript читаются плохо; тогда сервис просит описание бизнеса свободным текстом.
- Платные запросы к нейросети выполняют `GET /api/plan` и `GET /api/business/site-check`; они ограничены лимитами `AI_SPEND_*` на бизнес.
